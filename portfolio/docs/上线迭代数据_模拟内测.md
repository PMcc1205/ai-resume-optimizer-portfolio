# AI 简历优化助手｜21 上线迭代数据         

## 一、上线迭代情景

### 1.1 情景设定

- **目标**：模拟一个小范围作品集内测，用于验证流程可用性、事实解释是否可理解，以及用户是否愿意审阅并确认改写。
- **批次**：模拟基线批次 V0 和迭代批次 V1，各邀请 30 名符合目标用户画像的求职者；两批为独立用户，不视为严格 A/B 实验。
- **周期**：每批模拟观察 2 周；不假设真实上线、真实留存或真实投递结果。
- **核心迭代假设**：V1 优化事实缺口说明、证据依据展开、事实校验失败文案、手动修改后的状态提示和结果页信息层级。
- **样本限制**：样本量小且为便利招募，结果只用于发现产品问题，不用于证明因果关系或推广到全部求职者。

### 1.2 产品漏斗

| 指标 | V0 基线批次 | V1 迭代批次 | 变化 | 分母定义 |
| --- | ---: | ---: | ---: | --- |
| 邀请人数 | 30 | 30 | — | 发送体验邀请的用户 |
| 启动任务 | 27 | 28 | +1 | 至少进入新建任务页并填写一项内容 |
| 到达事实确认页 | 25 | 27 | +2 | 已提交任务并进入事实确认页 |
| 完成必要事实确认 | 21 | 25 | +4 | 到达事实确认页用户中，完成必要确认并继续 |
| 到达匹配分析页 | 20 | 24 | +4 | 成功进入匹配页的用户 |
| 到达 AI 优化页 | 18 | 23 | +5 | 成功进入优化页的用户 |
| 到达最终结果页 | 15 | 21 | +6 | 完成每条改写决策并进入结果页 |
| 复制最终简历 | 10 | 17 | +7 | 到达结果页用户中点击复制的用户 |

按各阶段真实分母计算，结果为：

- 启动率：90.0% → 93.3%；
- 启动用户到达最终结果页：55.6%（15/27）→ 75.0%（21/28），变化 +19.4 个百分点；
- 结果页复制率：66.7%（10/15）→ 81.0%（17/21），变化 +14.3 个百分点。

这些变化只能表述为“模拟情景下的观察结果”，不能表述为“上线后提升了 19.4 个百分点”。

### 1.3 优化行为与安全结果

| 指标 | V0 基线批次 | V1 迭代批次 | 分母定义 |
| --- | ---: | ---: | --- |
| 到达优化页后接受至少一条改写 | 11/18（61.1%） | 16/23（69.6%） | 到达优化页用户 |
| 到达优化页后手动修改至少一条 | 4/18（22.2%） | 8/23（34.8%） | 到达优化页用户 |
| 至少遇到一次校验不通过 | 7/18（38.9%） | 5/23（21.7%） | 到达优化页用户 |
| 接受且校验通过的改写 | 10/11（90.9%） | 15/16（93.8%） | 接受至少一条改写用户 |
| 接受后仍处于待校验/校验不通过 | 1/11（9.1%） | 1/16（6.3%） | 接受至少一条改写用户 |
| 用户查看详细事实依据 | 9/18（50.0%） | 17/23（73.9%） | 到达优化页用户 |

这里把“接受改写”和“接受且事实校验通过”分开。后者才是安全的采用指标；不能只追求接受率。

### 1.4 用户反馈与对应迭代

以下是为情景推演设计的典型反馈，不是真实访谈原话：

| 模拟反馈 | 可能暴露的问题 | V1 迭代动作 |
| --- | --- | --- |
| “我明明做过，为什么这里不能直接改？” | 事实缺口、能力缺口和表达缺口边界不清 | 在匹配页解释缺少哪条证据，增加补充经历入口，并保留“暂时跳过”状态 |
| “这句话看起来更专业，但我担心把职责写大了。” | 事实依据和校验理由隐藏太深 | 默认展示对应事实；将职责、数字、阶段等风险用自然语言说明 |
| “我想自己改几个词，再确认能不能用。” | 手动修改后的状态和重新校验路径不清 | 编辑后重置为“待事实校验”，只有当前版本校验通过才能采用 |
| “结果页看不出哪些内容是我原来的。” | 最终结果来源标识不够清楚 | 标识 AI 优化、手动优化和保留原文，并确保复制内容与页面一致 |

## 二、上线后应该关注哪些指标

### 2.1 产品漏斗指标

这些指标回答“用户能不能走完流程”：

- 任务启动率；
- JD 提交成功率；
- 事实确认完成率；
- 匹配分析到达率；
- 诊断到优化转化率；
- 优化页到结果页完成率；
- 结果复制率；
- 返回修改后再次进入结果页的成功率。

漏斗指标必须同时记录事件时间、任务 ID、页面步骤和失败原因，不能只保存最后一个页面。

### 2.2 AI 质量与真实性指标

这些指标回答“用户采用的内容是否可信”：

- 生成后事实校验通过率；
- 校验不通过率及按风险类型分布；
- 接受且校验通过率；
- 接受后仍为待校验或失败的比例；
- 用户手动确认事实的比例；
- 用户拒绝改写的比例；
- 重新生成率；
- 抽样人工复核的职责升级、数字幻觉、项目状态升级、跨项目混写比例；
- 正常改写被拦截的误报率。

用户行为数据不能替代 Gold 评测。真实性指标仍应通过冻结案例、人工抽样和规则审计共同判断。

### 2.3 用户理解与信任指标

建议在完成结果后进行 2～3 个简短问题的可选反馈：

- 用户是否理解为什么改写或拦截；
- 用户是否能找到对应事实依据；
- 用户是否愿意再次使用；
- 用户是否认为最终文本仍准确代表自己。

每个问题需要提前定义选项、评分方式和有效回答数，不能直接用“理解人数”作为未经定义的结果指标。

### 2.4 系统稳定性指标

- 页面或接口错误率；
- 结构约束校验失败率；
- 模型重试率；
- 超时率；
- 结果合并失败率；
- 刷新后状态恢复成功率；
- 复制内容与页面显示一致率。

这些指标用于区分“模型判断错”与“流程、结构或前端状态错”。

## 三、指标不好时，可能是什么问题、如何解决

| 异常指标 | 更可能的原因 | 诊断方式 | 优先解决方案 |
| --- | --- | --- | --- |
| 任务启动率低 | 入口价值不清、输入成本高、JD/简历要求不明确 | 查看入口点击、表单字段停留和退出位置；访谈未启动用户 | 提供演示入口；减少首屏解释；明确所需输入和预计流程 |
| 事实确认完成率低 | Fact 太多、风险提示难懂、用户不知道确认依据 | 看停留时长、展开详情、删除/编辑行为和退出步骤 | 只优先确认高风险事实；增加原文定位；区分“待确认”和“信息不足” |
| 匹配页到诊断页转化低 | 证据映射难以理解、缺口动作不明确、阻塞条件不透明 | 对比不同 Match Status 的退出率，观察补充/跳过按钮使用 | 使用“岗位要求—事实—缺口”三段式说明；明确哪些问题阻塞、哪些可跳过 |
| 优化页到结果页完成率低 | 改写相关性不足、用户不信任、决策按钮难找 | 看接受、拒绝、手动修改、重新生成和未决策分布 | 优先展示改写依据；降低无关问题噪音；明确“接受且校验通过”规则 |
| 接受率高但校验通过率低 | 文案看起来专业，但模型经常越过事实边界 | 抽样查看职责、数字、阶段和结果风险；按风险类型聚合 | 优先收紧事实白名单、生成后校验和风险提示；不要直接追求接受率 |
| 接受率低但校验通过率高 | 用户认为改写不够贴合岗位或表达收益不明显 | 分析拒绝原因、原文/改写对照和岗位要求关联 | 改善诊断到改写的上下文；展示改写目的；保留用户拒绝原文的选择 |
| 手动修改率异常高 | AI 文本不符合用户语气、过于激进或过于模板化 | 抽样对比编辑前后差异，统计被改动的职责、数字和句式 | 增加表达风格选项；缩小改写范围；手动修改后强制重新校验 |
| 校验不通过率高 | Prompt 约束不足、事实输入不完整、规则边界覆盖不足 | 按 violationType、模型响应、重试和 Fact 来源分析 | 先做 Failure Analysis；区分结构错误与语义错误；再做通用规则修复 |
| 复制率低 | 结果页价值不清、复制按钮不可见、最终内容不完整 | 看结果页停留、滚动、复制按钮点击和返回修改行为 | 突出最终简历区域；保证复制内容与页面一致；显示采用/保留来源 |
| 刷新恢复失败 | sessionStorage 快照不完整、版本不一致或状态重算 | 记录刷新前后任务状态和关键存储键 | 使用任务级状态快照；校验版本；缺失时给出恢复或重新开始提示 |
| 结构约束错误或重试率高 | 模型输出不稳定、提示词与结构约束不一致 | 记录错误路径、错误类型、期望值、实际值和重试次数 | 先修正 Prompt/Schema 契约；保留安全调试信息；禁止静默补业务字段 |

## 四、建议的事件埋点

如果未来真实上线，至少记录以下不含简历正文的事件：

| 事件 | 关键属性 |
| --- | --- |
| `demo_started` / `task_started` | mode、taskId、source |
| `jd_submitted` | jobTitle 是否存在、是否成功 |
| `fact_review_opened` | pendingCount、blockingCount |
| `fact_confirmed` / `fact_edited` / `fact_deleted` | factType、riskLevel、step |
| `mapping_viewed` | matchStatus、gapType |
| `diagnosis_selected` | priority、optimizable |
| `rewrite_viewed` | validationStatus、usedFactCount |
| `rewrite_accepted` / `rewrite_rejected` | validationStatus、decision |
| `rewrite_edited` | editLengthDelta、revalidationRequired |
| `validation_completed` | status、violationTypes、retryCount |
| `result_viewed` / `result_copied` | adoptedCount、retainedCount、factGapCount |
| `workflow_error` | step、errorCode、errorType |

不要在埋点中保存完整简历正文、API Key、Authorization 或不必要的个人信息。产品指标和隐私边界必须同时设计。
